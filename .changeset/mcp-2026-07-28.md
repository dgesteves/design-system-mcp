The MCP server speaks the 2026-07-28 protocol revision as well as the 2025 one, on the same stdio command.

- **Both eras.** A client's first message picks the era: `server/discover` or a request with the 2026-07-28 `_meta` gets the stateless revision, and an `initialize` request gets the 2025 handshake, served as before. On 2026-07-28, `server/discover` returns the supported versions, capabilities, `serverInfo` and instructions; every result carries `resultType`; list results carry `ttlMs` and `cacheScope` (the tools, prompts and resource templates for an hour, the component resources not at all, all private); `tools/list` keeps one order; and an unsupported version gets `-32022` naming the supported ones.
- **Finding the project.** `--root`, a config file in the working directory, or the working directory itself when it holds a project (a `package.json` or `components.json`) come first. MCP roots, deprecated in 2026-07-28, are the fallback, for a 2025-era client that starts the server outside any project.
- **SDK.** The server moves from `@modelcontextprotocol/sdk` 1.x to `@modelcontextprotocol/server` 2.x, the SDK line that implements 2026-07-28. Its install no longer brings the SDK's HTTP stack (Express, Hono). `check_ui`'s output schema describes a fix's `range` as an array of two integers rather than a tuple, which clients that validate structured content as draft-07 rejected.
- For library users: `createServer` returns the v2 SDK's `McpServer`, and `serveStdio` resolves to a handle with `close()` rather than to the `McpServer`.
